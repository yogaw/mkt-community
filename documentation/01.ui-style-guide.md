# UI Style Guide

The member-facing UI follows a dark dashboard style: near-black canvas, slightly lighter
panels, hairline borders and a single mint-green accent. The reference is a trading
dashboard layout — sidebar navigation on the left, page title and search in a top bar,
content in dark cards. Content and wording stay specific to Piranha.

## Theme tokens

Defined once in `src/app/globals.css` under `@theme` (Tailwind v4 generates the
utilities). Always use tokens instead of raw Tailwind grays so the palette stays editable
in one file.

| Token | Value | Utility examples | Use |
|-------|-------|------------------|-----|
| `canvas` | `#0b0d0e` | `bg-canvas` | Page background |
| `panel` | `#15181a` | `bg-panel`, `border-edge` | Cards, sidebar, inputs |
| `panel-raised` | `#1d2124` | `bg-panel-raised` | Inputs, badges, skeletons, hover surfaces |
| `edge` | `#272c30` | `border-edge` | All hairline borders |
| `ink` | `#f4f6f7` | `text-ink` | Headings, primary text |
| `ink-muted` | `#a3adb2` | `text-ink-muted` | Body and secondary text |
| `ink-faint` | `#6e777c` | `text-ink-faint` | Meta text, timestamps, section labels |
| `accent` | `#52d789` | `bg-accent`, `text-accent` | Primary buttons, active states, links, highlights |
| `accent-strong` | `#3fc97a` | `hover:bg-accent-strong` | Accent hover |
| `accent-ink` | `#072b1b` | `text-accent-ink` | Text on accent surfaces |
| `down` | `#ef6f6f` | `text-down`, `bg-down/10` | Errors, negative values |

Amber (`amber-300` on `amber-400/10`) is reserved for warning states such as the
Inactive/Expired membership badges.

## Application shell

`src/components/layout/app-shell.tsx` wraps every authenticated page via the
`src/app/(member)/layout.tsx` route group:

- Left sidebar: brand and a flat navigation list — Home, Insights, Stocks, Videos, Live,
  Watchlist, Profile. There is no Search entry; global search lives in the top bar
  (placeholder: "Search stocks, insights, videos...", submits to `/search?q=`). The active
  item gets `bg-panel-raised` with accent text. On mobile the sidebar becomes an
  off-canvas drawer behind a hamburger button.
- Top bar: page title resolved from the pathname, the global search box and an avatar
  image link to Profile.
- The Login page lives outside the route group and renders without the shell; the public
  proposal page (`/proposal`) also renders without the shell.

## Dashboard layout

Page content is capped at a 1320px max width and centered (`mx-auto max-w-[1320px]`) so
the product reads as editorial financial software rather than a stretched admin panel.
The dashboard hierarchy: welcome header, market snapshot, Today's Briefing hero, What
Matters Today, Stocks in Focus, Sector Pulse, Upcoming Live, Latest Market Insights.
Green is reserved for the primary CTA, positive movement, active navigation and important
indicators; signed negative values use `down`. Market figures come from placeholder data
in `src/features/home/market-data.ts` until a real IDX source is connected.

## Component conventions

- Buttons: two variants — primary (solid accent green with `accent-ink` text) and
  secondary (`bg-panel-raised` with an `edge` border) for non-primary actions such as
  Add to Calendar. Hero CTAs use normal width (`w-auto`), not full-width bands.
- Cards: `rounded-xl border border-edge bg-panel`; hover states brighten the border
  (`hover:border-ink-faint`) rather than adding shadows. Hero-level panels may use
  `rounded-2xl`.
- Badges (type, category, platform): `rounded-full bg-panel-raised` pills; type badges use
  accent text, category and platform use muted text. Movement chips use `bg-accent/10
  text-accent` or `bg-down/10 text-down`.
- Links out of context (section actions, back links): accent for section actions,
  `text-ink-muted hover:text-ink` for back links.
- Error/empty panels reuse the card recipe; empty states keep a dashed `border-edge`.
- Text scale stays small and dense: `text-sm` bodies, `text-lg` section titles,
  `text-2xl`/`text-3xl` hero headlines.

## Content rules

Plain-text labels only; no emoji or decorative glyphs in UI copy, seed content or
documentation. Icons are inline SVG (currently only the hamburger and future search
icon), never emoji.
